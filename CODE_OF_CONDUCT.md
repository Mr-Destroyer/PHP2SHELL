# Code of conduct

## The short version

Be useful. Argue about evidence, not about people. Assume the other person is
competent until proven otherwise, and then prove it with a test case rather than
an insult.

## Expected behaviour

- **Evidence over assertion.** In a repo about proving whether a host is exposed,
  "I think" is the start of a conversation, not the end of one.
- **Respect the authorisation boundary.** Do not ask for help testing a target
  you do not own or have written permission to test. Such requests will be
  declined without discussion.
- **Credit generously.** If someone's lab notes, offset derivation or failed
  approach saved you time, say so in the commit or the issue.
- **Accept corrections.** A wrong claim in a security tool is worse than no tool.
  When someone shows your verdict is wrong, that is the system working.

## Unacceptable behaviour

- Harassment, personal attacks, or discriminatory language of any kind.
- Publishing another person's private infrastructure, credentials, or target list.
- Using issues or PRs to request or share working exploit payloads for targets
  the requester does not control.
- Dismissing a report because it is a negative result. "Stage 3 does not land"
  is exactly the kind of finding this repository exists to record.

## Scope

This code applies to issues, pull requests, commit messages, and any discussion
in repository spaces.

## Enforcement

Report concerns to **security@zim.dev**. Reports are handled privately. Outcomes
range from a request to rephrase, through comment deletion, to a permanent ban
from the repository — proportionate to the behaviour, and explained to the person
concerned.
